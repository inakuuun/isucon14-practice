# 実装基準（ISUCON）

## SQLとインデックス

- インデックスは対象クエリの `WHERE` の等価条件 → 範囲条件 / `ORDER BY` の順でカラムを並べる。
- インデックスは初期化時に適用されるスキーマファイルに追加する。既存の追加方法（`CREATE TABLE` 内か、末尾の `ALTER TABLE ... ADD INDEX` か）と命名に合わせる。
- 初期化処理がスキーマを再作成しない場合は、インデックスやカラム追加が確実に適用される経路を確認する。
- `SELECT *` を減らす変更は、そのカラムを後続処理で使っていないことを確認してから行う。
- 主キーやユニーク制約の変更は、既存データと書き込み処理の両方で一意性が保たれる場合だけ行う。

## N+1と集計

- ループ内のクエリは、`IN (?)` や `JOIN` でまとめる。結果を `map` に詰め直し、元の順序を維持する。
- `IN` の対象が空の場合のエラーや不正なSQLを避けるため、事前に早期returnする（例: `sqlx.In` は空スライスでエラーになる）。
- 毎回全件を集計している値（合計、最新値、件数、平均など）は、書き込み時に保持する方式を検討する。その場合は書き込み経路をすべて洗い出して更新漏れを防ぎ、初期データ分の値も初期化処理で作る。
